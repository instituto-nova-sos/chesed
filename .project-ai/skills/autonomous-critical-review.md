# Skill: Autonomous Critical Review

## Purpose

Run the `reviewer` agent over a feature branch's diff and write its verdict to a
**verifiable file** — `tasks/review-<branch>.md` — in the reviewer's report
format. This converts the reviewer from an assistive, in-chat opinion into an
**executable, file-backed gate**: `make deliver` (step 6) reads this file and
**fails the pipeline** unless the verdict is `APPROVE`.

This skill is the critical-review gate of the autonomous delivery pipeline. It is
invoked by `.project-ai/workflows/autonomous-delivery.md` and consumed by the
`deliver-review-gate` target in the root `Makefile`.

## When to Use / Trigger

- As step 6 of `make deliver` (the autonomous delivery pipeline), before the DoD
  gate and the `READY-FOR-PR` banner.
- Every time `make deliver` is (re-)run, including each auto-remediation cycle —
  the verdict file is **regenerated** so the gate always reflects the current diff.
- When a user asks for "the critical review", "the reviewer verdict file", or
  "the blocking review gate" for the current branch.

## Push Boundary (non-negotiable)

This skill is read-only with respect to remote state. It reads the local diff and
writes one local file. It **never** runs `git push`, `gh pr create`, or
`gh pr merge`. Delivery ends at local commits + this APPROVE file + the printed
`READY-FOR-PR` banner. See `.project-ai/workflows/autonomous-delivery.md`.

## Role / Expertise

Drives the existing `reviewer` agent (`.project-ai/agents/reviewer.md`) — a senior
code reviewer with blocking authority — applying the project's quality gates,
clean-code categories, and complexity thresholds.

## Inputs

| Input | Required | Source |
|-------|----------|--------|
| Branch under review | Yes | `git rev-parse --abbrev-ref HEAD` |
| Branch diff | Yes | `git diff main...HEAD` (changes since the branch left `main`) |
| Changed file list | Yes | `git diff --name-only main...HEAD` |
| Commit narrative | Yes | `git log --oneline --name-only main..HEAD` (RED→GREEN→REFACTOR story) |
| Reviewer agent | Yes | `.project-ai/agents/reviewer.md` (verdict format, gate table) |
| Quality gates | Yes | `docs/quality/quality-gates.md` (New Code gate) |
| Clean code guidelines | Yes | `docs/quality/clean-code-guidelines.md` |
| Complexity guidelines | Yes | `docs/quality/complexity-guidelines.md` |
| TDD rule | Yes | `.project-ai/rules/tdd-enforcement.md` (RED→GREEN commit narrative check) |

## Process

1. **Resolve the branch and diff.**
   - `BRANCH=$(git rev-parse --abbrev-ref HEAD)`.
   - Collect the diff with `git diff main...HEAD` and the changed-file list with
     `git diff --name-only main...HEAD`. Use the three-dot form so the review
     covers only what this branch added relative to `main`.
   - Collect the commit narrative with `git log --oneline --name-only main..HEAD`
     so the reviewer can confirm the RED→GREEN→REFACTOR story holds (per
     `.project-ai/rules/tdd-enforcement.md`). The authoritative TDD ordering check
     remains the `pre-review` hook; here the reviewer only corroborates it.

2. **Invoke the reviewer agent.** Run `.project-ai/agents/reviewer.md` against the
   collected diff, file list, and commit narrative. The reviewer evaluates, with
   no skipping:
   - **New Code Quality Gate** (bugs, vulnerabilities, security hotspots, coverage,
     duplication, maintainability/reliability/security ratings, high-severity count).
   - **Clean Code** categories: Consistency, Intentionality, Adaptability, Responsibility.
   - **Complexity** thresholds per changed function (Go and React/TS limits).
   - **Issues** per file, by severity: BLOCKER > MAJOR > MINOR > SUGGESTION.
   - **Verdict**: exactly one of `APPROVE`, `REQUEST_CHANGES`, `NEEDS_DISCUSSION`.

3. **Write the verdict file** to `tasks/review-<branch>.md` (overwrite any prior
   run for this branch) using the reviewer's **Review Report Format** verbatim
   (see Output Contract). The verdict line MUST be machine-checkable.

4. **Return control to the pipeline.** The `deliver-review-gate` target greps the
   file: `APPROVE` lets the pipeline continue; anything else fails it. On a
   non-APPROVE verdict, the orchestrator runs the auto-remediation loop
   (`.project-ai/workflows/autonomous-delivery.md`) and re-invokes this skill.

## Output Contract — `tasks/review-<branch>.md`

The file MUST follow the reviewer agent's report format and MUST contain a final
verdict line the Makefile can match. The Makefile matches a line of the form
`### Verdict: APPROVE` (also accepts `## Verdict: APPROVE`). Keep the verdict
token uppercase and on its own heading line.

```markdown
# Critical Review — <branch>

_Generated by the autonomous-critical-review skill over `git diff main...HEAD`._
_Branch: <branch> · Reviewed commits: main..HEAD · Date: <ISO-8601>_

## Quality Gate: [PASS / FAIL]

### Conditions
| Condition | Status | Details |
|-----------|--------|---------|
| Bugs | PASS/FAIL | [count] |
| Vulnerabilities | PASS/FAIL | [count] |
| Security Hotspots | PASS/FAIL | [reviewed/total] |
| Coverage | PASS/FAIL | [percentage] |
| Duplication | PASS/FAIL | [percentage] |
| Maintainability | PASS/FAIL | [rating] |
| Reliability | PASS/FAIL | [rating] |
| Security | PASS/FAIL | [rating] |

### Clean Code Assessment
| Category | Status | Findings |
|----------|--------|----------|
| Consistency | PASS/FAIL | [details] |
| Intentionality | PASS/FAIL | [details] |
| Adaptability | PASS/FAIL | [details] |
| Responsibility | PASS/FAIL | [details] |

### Issues
[Per file, by severity: BLOCKER > MAJOR > MINOR > SUGGESTION]

### Complexity Report
[Functions exceeding thresholds with values and refactoring guidance]

### TDD Narrative
[Confirm RED→GREEN→REFACTOR commit order holds per tdd-enforcement.md, or flag the gap]

### Verdict: APPROVE
[Required fixes if REQUEST_CHANGES; discussion points if NEEDS_DISCUSSION;
 on the 3rd non-converged auto-remediation cycle, record the IMPASSE here per
 autonomous-delivery.md and stop for human decision.]
```

## How the verdict gates the pipeline

- `make deliver` runs `deliver-review-gate`, which:
  - **FAILS** if `tasks/review-<branch>.md` is missing (the skill was not run).
  - **FAILS** if the verdict line is not `APPROVE` (`REQUEST_CHANGES` /
    `NEEDS_DISCUSSION` / IMPASSE all block).
  - **PASSES** only on `### Verdict: APPROVE`.
- A passing gate is necessary but not sufficient: the DoD gate (step 7) still runs
  before `READY-FOR-PR`.

## Quality Bar

- Evaluate every quality-gate condition — no skipping (mirrors the reviewer agent).
- Provide file paths and line ranges for every finding.
- Never write `APPROVE` while any New Code gate condition fails or any
  BLOCKER/MAJOR issue is open.
- Regenerate the file on every run so the gate never reads a stale verdict.
